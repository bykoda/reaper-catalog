# REAPER Catalog для Telegram

В комплекте 258 тем, 141 автор, 180 дополнительных источников и 220 изображений. Побайтово одинаковые изображения используют один файл, поэтому PNG-файлов 213. Каталог открывается внутри Telegram и в обычном браузере.

## 1. Разместите каталог

**GitHub Pages с автоматической публикацией.**

1. Распакуйте ZIP. Создайте публичный репозиторий на GitHub, например `reaper-catalog`, и клонируйте его через GitHub Desktop. Скопируйте в репозиторий содержимое папки `reaper-mini-app` из архива. В корне должны лежать `site`, `tools`, `README.md` и `.github`.
2. В GitHub Desktop сделайте **Commit** и **Push origin** в основную ветку. В GitHub откройте **Settings → Pages → Build and deployment → Source → GitHub Actions**.
3. Откройте **Actions → Publish REAPER catalog → Run workflow** и выберите основную ветку. После успешного запуска возьмите ссылку сайта из **Settings → Pages**. Пример адреса `https://ВАШ-ЛОГИН.github.io/reaper-catalog/`.
4. Откройте ссылку в браузере. Проверьте поиск, одну карточку с изображением и вкладку «Авторы».

Веб-сайт публичный. В репозиторий загружайте комплект для публикации. Исходный экспорт Telegram, токены бота и личные резервные копии отметок храните у себя. [Настройка источника GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site)

**Другой HTTPS-хостинг.** Загрузите содержимое `site` в папку сайта, сохранив структуру `media/`. Используйте публичный HTTPS-адрес каталога. Если хостинг выставляет заголовки для встраивания, разрешите открытие страницы из Telegram Web.

## 2. Подключите к Telegram

1. Откройте [@BotFather](https://t.me/BotFather). Если бот уже есть, используйте его. Для нового отправьте `/newbot`, задайте имя и свободный username, оканчивающийся на `bot`. Сохраните выданный токен у себя. Для запуска этого каталога токен в файлах, сервер бота и обработчик команд не нужны. [Создание бота](https://core.telegram.org/bots/features#creating-a-new-bot)
2. Отправьте `/setmenubutton` и выберите бота. По подсказкам BotFather укажите HTTPS-адрес сайта и название кнопки **Каталог REAPER**. Ту же настройку можно открыть через **Bot Settings → Menu Button**. [Кнопка меню](https://core.telegram.org/bots/webapps#launching-mini-apps-from-the-menu-button)
3. Откройте личный чат с ботом и нажмите **Каталог REAPER**. Чтобы добавить кнопку запуска в профиле и ссылку вида `https://t.me/ИМЯ_БОТА?startapp`, настройте **Main Mini App** у того же бота в BotFather и укажите тот же HTTPS-адрес. [Основное мини-приложение](https://core.telegram.org/bots/webapps#launching-the-main-mini-app)
4. Проверьте на телефоне поиск, открытие ссылки, закрытие карточки кнопкой Telegram «Назад» и сохранение PNG, TXT и JSON. Для PNG в галерее есть **Открыть PNG в браузере**. Для TXT можно скопировать текст, а в резервной копии отметок можно скопировать или вставить JSON. Скачивание и системное меню «Поделиться» зависят от клиента. [Требования Telegram к нативным загрузкам](https://core.telegram.org/bots/webapps#downloadfileparams)

Telegram требует HTTPS для опубликованной Mini App. Официальный SDK подключён в `head` перед скриптами каталога. Приложение использует тему Telegram по умолчанию и учитывает безопасные отступы экрана. Отметки хранятся локально для домена сайта и клиента. Для переноса из исходного HTML экспортируйте отметки и импортируйте JSON в Mini App. Каталог не использует данные профиля Telegram. Если позже добавите авторизацию, проверяйте `initData` на сервере. [HTTPS в Bot API](https://core.telegram.org/bots/api#webappinfo) · [SDK и проверка данных](https://core.telegram.org/bots/webapps#initializing-mini-apps)

## 3. Обновляйте каталог

**Ручная синхронизация данных.** Из папки проекта выполните в PowerShell. Нужен Python 3, дополнительные библиотеки не требуются.

```powershell
python tools/update_catalog.py "C:\папка\новый-reaper-scripts-catalog.html"
```

Импорт читает блок данных из HTML той же структуры, проверяет ссылки и PNG и обновляет `site/catalog.json` и `site/media`. Для публикации в GitHub закоммитьте изменения в `site` и отправьте их в основную ветку. Для другого хостинга загрузите новые PNG перед заменой `catalog.json`. Адрес в BotFather остаётся прежним.

**Автопубликация готова.** GitHub Actions при отправке в основную ветку проверяет данные, контрольные суммы PNG и синтаксис JavaScript, затем публикует папку `site`. При ошибке проверки предыдущий выпуск остаётся на сайте. Внешние действия закреплены на конкретных коммитах. Права на публикацию выдаются только шагу развёртывания. Токен Telegram и персональный токен GitHub для этого сценария не нужны. [Публикация Pages через Actions](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages) · [Закрепление действий по SHA](https://docs.github.com/en/actions/reference/security/secure-use)

**Автоматическое пополнение требует источника.** Исходный HTML содержит снимок каталога. Для обновления без ручного экспорта нужен управляемый вами источник, например отдельный репозиторий, где появляется новый экспорт. Проверка по расписанию может брать файл с заранее заданного HTTPS-адреса с ограничением размера и времени, извлекать только данные и предлагать изменения отдельным pull request. Перед слиянием проверяйте удалённые карточки, изменившиеся ссылки и права на новые изображения. Ошибка загрузки или проверки оставляет опубликованный каталог в прежнем состоянии. Расписание в комплекте выключено до появления постоянного источника. [Расписание GitHub Actions](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule)

## Локальная проверка

```powershell
python tools/update_catalog.py
python -m http.server 8000 --bind 127.0.0.1 --directory site
```

Откройте `http://127.0.0.1:8000/` в браузере. Для проверки внутри Telegram нужен опубликованный HTTPS-адрес. Изображения загружаются при прокрутке. Для просмотра исходного каталога без сети используйте исходный автономный HTML.
